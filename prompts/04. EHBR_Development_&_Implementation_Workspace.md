## 4. Figma-to-Code Implementation

Treat the approved Figma design as the primary visual and interaction reference.

For every requested screen or feature:

1. Identify the relevant Figma frame.
2. Inspect its layout, components, content, and expected interactions.
3. Locate the existing implementation.
4. Compare the current implementation with the design.
5. Identify missing or inconsistent functionality.
6. Determine which application layers need modification.
7. Implement the approved changes.
8. Compare the result against the reference design.

Do not rebuild screens unnecessarily when an existing implementation can be improved.

Preserve existing visual conventions, reusable components, theme styles, and navigation patterns unless a redesign is explicitly requested or justified.

## 5. Development Workflow

Follow this process for each task:

**Step 1 — Inspect**

Read relevant files and understand the current implementation before changing anything.

**Step 2 — Analyze**

Identify the problem, expected behavior, dependencies, affected files, and potential risks.

**Step 3 — Plan**

Present a practical implementation plan with affected files, UI changes, backend requirements, and testing criteria.

**Step 4 — Approval**

Wait for my approval before modifying files.

**Step 5 — Implement**

Make focused changes while preserving existing functionality.

**Step 6 — Test**

Run appropriate tests, builds, and manual checks. Report actual results.

**Step 7 — Review**

Inspect the changes and identify possible regressions or remaining limitations.

**Step 8 — Document**

Summarize modified files, implemented functionality, test results, and the next recommended task.

## 6. Code and Project Protection

- Never rewrite the entire application to implement a small feature.
- Do not unnecessarily alter unrelated screens or modules.
- Keep MAM, WAM, backend, and database responsibilities properly separated.
- Do not silently modify existing API contracts.
- Never expose API keys, credentials, access tokens, or environment secrets.
- Do not remove existing functionality without approval.
- Avoid destructive database operations.
- Do not commit or push changes without my approval.
- Keep changes small, understandable, and maintainable.
- Report any missing configuration or dependency honestly.

## 7. Testing and Quality

Do not consider a feature complete simply because its interface looks correct.

Where applicable, verify:

- UI and Figma alignment.
- Navigation and interactions.
- Input validation.
- Loading, success, error, and empty states.
- API communication.
- Database persistence.
- Authentication and authorization.
- Offline handling.
- Responsive layouts.
- Automated tests and regression checks.

Distinguish code inspection from functionality that has actually been executed and tested.
